# Catatan Code Review & Keputusan Arsitektural

Minta AI me-review kode kalian, lalu putuskan saran mana yang diterima.
Menolak saran AI dengan alasan yang jelas adalah hal yang baik.

**Prompt audit yang dipakai (Static Code Analysis):**
"Lakukan audit kode statis (*Static Code Audit*) secara komprehensif pada arsitektur KoreksiKoding di `src/lib/api.ts`, `src/store/AppContext.tsx`, `src/pages/RiwayatPage.tsx`, dan `src/lib/crypto.ts`. Fokuskan evaluasi pada: kerentanan API key (SecOps), ketahanan *parser* JSON dari halusinasi LLM, identifikasi kebocoran memori (*memory leaks*), dan kemacetan UI utama (*main thread blocking*) di perangkat seluler. Berikan rekomendasi mitigasi konkret per modul."

| No | Saran dari AI (Code Smell / Vulnerability) | Keputusan Tim | Justifikasi Teknis (Engineering Justification) | Implementasi Kode yang Berubah |
|---|---|---|---|---|
| 1 | **[Kritis]** Hindari menyimpan API Key dalam format teks mentah (*plaintext*). Hapus seluruh jejak `console.log` yang mengekspos variabel kredensial. | **Diterima** | Rekomendasi keamanan absolut. Kredensial *plaintext* di `localStorage` sangat rentan terhadap serangan XSS (pencurian token). Jejak log saat fase *debugging* juga membahayakan privasi penguji. | `src/lib/crypto.ts`: Mengimplementasikan kriptografi asimetris AES-GCM dengan PBKDF2 (`encryptApiKey`/`decryptApiKey`). `src/lib/api.ts`: Modifikasi `getProviders`/`saveProviders`. Seluruh `console.log` berisi *payload* API dihapus total. |
| 2 | **[Ketahanan]** Pemanggilan `JSON.parse` secara langsung akan memicu *fatal crash* jika AI (khususnya *reasoning model* seperti Groq) mengembalikan tag `<think>`. Buat *parser* yang toleran. | **Diterima** | Terbukti pada Kasus Uji U01, model LLM sering merusak *markdown fence*. Mengandalkan `JSON.parse` mentah adalah praktik rekayasa yang rapuh (*brittle engineering*). | `src/lib/api.ts`: Mengganti alur ekstraksi dengan *Finite State Machine* di `extractJSON()`, injeksi `stripThinkingBlocks()`, serta penambahan fungsi pembersih *noise* `sanitizeFixedCode()`. |
| 3 | **[Stabilitas State]** Terapkan modul `ErrorBoundary` secara global. Tambahkan *event listener* `beforeunload` untuk melakukan *flush* state editor sebelum browser dimuat ulang. | **Diterima** | Tanpa `beforeunload`, *state* lokal (Volatile Memory) di editor akan lenyap jika terjadi *reload* tak sengaja. `ErrorBoundary` mencegah aplikasi mengalami *White Screen of Death* jika terjadi anomali *render*. | `src/components/ErrorBoundary.tsx` diselimutkan ke `App.tsx`. Di `AppContext.tsx`, kami memasang *listener* jendela untuk sinkronisasi `kk_koreksi_editor_state` secara agresif. |
| 4 | **[Optimasi]** Lakukan validasi kekosongan model AI (*Pre-flight check*) sebelum eksekusi berlanjut, agar tidak membakar kuota *rate limit* secara percuma. | **Diterima** | Ini adalah implementasi *Circuit Breaker Pattern*. Memotong kuota lokal di awal sebelum memastikan koneksi API tersedia adalah pemborosan siklus komputasi (*Resource Leak*). | `AppContext.tsx`: Memodifikasi `runAnalysis()`. Menambahkan validasi `availableModels`. Jika kosong, langsung tolak dengan *Toast* intersepsi `settings.validationRequired` tanpa menyentuh kuota harian. |
| 5 | **[Arsitektur]** Pindahkan seluruh logika pemanggilan AI ke *Backend Server/Proxy* (Node.js) agar API Key aman sepenuhnya dan manajemen *rate limit* terpusat. | **DITOLAK TEGAS** | Rekomendasi ini bertentangan secara frontal dengan Spesifikasi Inti Proyek: "Arsitektur Zero-Data Retention (Tanpa Backend)". Pembuatan *backend* akan menimbulkan Biaya HPP Server bagi sekolah. Perlindungan XSS, batas lokal (`kk_rate_limit`), dan Kriptografi Klien (BYOK) sudah cukup kebal. | Tidak ada kode yang diubah. Penolakan ini didokumentasikan di `docs/01-spesifikasi.md` pada bagian *Di Luar Cakupan (Out of Scope)*. |
| 6 | **[Performa]** Tinggalkan `IndexedDB` dan migrasi sepenuhnya ke `localStorage` untuk menyimpan riwayat agar struktur antarmuka kode lebih sederhana (*Synchronous*). | **DITOLAK TEGAS** | Ini adalah saran performa yang sangat buruk dari AI. Kapasitas `localStorage` dibatasi ~5MB dan beroperasi secara *Synchronous* (memblokir *Main UI Thread*). Karena *payload* JSON riwayat analisis kami besar, menggunakan `localStorage` akan memicu macet (*UI jank/lag*) pada HP spesifikasi rendah. `IndexedDB` bekerja secara *Asynchronous* dan mampu menyimpan hingga ratusan MB tanpa macet. | Tim mempertahankan arsitektur di `src/lib/db.ts` dengan membungkus antarmuka `idb` v2 pada *object store* `history` dan `challenges`. Dukungan filter/pencarian tetap optimal. |
